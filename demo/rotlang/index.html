quickstart

Run a file from the terminal:

git clone <this repo> && cd RotLang
npm install
node bin/brainrot.js run examples/fizzbuzz.brainrot

Or skip the install entirely — every snippet on this page has a run it button that opens it in the browser playground. Files end in .brainrot. No semicolons; newlines end statements; btw starts a comment.

variables

cook declares, be assigns. Reassigning doesn't need cook — but using a variable that was never cooked is an error. 

cook aura be 100
aura be aura + 1
yap("aura level:", aura)

Compound assignment works too — += -= *= /= %= — on plain variables, array slots, and object fields. += concatenates when the left side is a string. 

cook aura be 100
aura += 50

cook squad be [1, 2, 3]
squad[0] *= 2

cook bird be {y: 250, vel: 0}
bird.y += bird.vel

yap(aura, squad, bird)

Truthiness: only cap and ghost are falsy. 0 and "" are truthy — stay woke. + concatenates when either side is a string and coerces the other side.

conditionals

sus = if, mid = else-if, nah = else. Equality reads like speech: is and aint (or == / !=). Logic: and, or, not — both short-circuit. 

cook aura be 777

sus (aura > 1000) {
  yap("elite tier")
} mid (aura > 500 and aura aint ghost) {
  yap("mid tier, respectable")
} nah {
  yap("npc behavior")
}

loops

grind is while:

cook hp be 3
grind (hp > 0) {
  yap("still grinding, hp:", hp)
  hp be hp - 1
}

finna is a range loop — inclusive on both ends, optional by step, counts down automatically when from > to: 

finna (i from 1 to 5)        { yap(i) }
finna (i from 10 to 0 by -5) { yap(i) }

vibin is for-each — arrays, string characters, or object keys: 

vibin (member in ["kai", "livvy", "duke"]) {
  yap(member, "pulled up")
}

dip breaks out, skip continues to the next iteration.

functions

sigma declares, yeet returns. No yeet means the function returns ghost. Recursion and closures both work. 

sigma fib(n) {
  sus (n < 2) { yeet n }
  yeet fib(n - 1) + fib(n - 2)
}
yap(fib(10))

Functions are values. An anonymous sigma is an expression — pass it straight to map or keep: 

cook nums be [1, 2, 3, 4, 5]
yap(map(nums, sigma (n) { yeet n * n }))
yap(keep(nums, sigma (n) { yeet n % 2 is 0 }))

Closures capture their scope for real:

sigma makeCounter() {
  cook n be 0
  yeet sigma () {
    n be n + 1
    yeet n
  }
}
cook clicks be makeCounter()
clicks()
yap("clicked", clicks(), "times")

arrays

Zero-indexed. Index assignment works. Out-of-bounds is an error, not ghost.

cook squad be ["rizz", "gyatt"]
push(squad, "ohio")
squad[0] be "RIZZ"
yap(squad, "·", count(squad), "members")
yap(sort([3, 1, 2]), chop(squad, 0, 2))

objects

String-keyed maps. Dot access for identifier-ish keys, brackets for anything. Reading a missing key gives ghost — use has() to check. Setting a new key just works. 

cook user be {name: "drake", followers: 100}
user.followers be user.followers + 1
user.verified be nocap
yap(user.name, "→", user)
yap(keys(user), has(user, "aura"))

Objects + vibin make honest work possible:

cook freq be {}
vibin (w in rip("cap no cap no no", " ")) {
  sus (has(freq, w)) { freq[w] be freq[w] + 1 }
  nah { freq[w] be 1 }
}
vibin (k in sort(keys(freq))) { yap(k, freq[k]) }

errors

Slang delivery, real line numbers:

yo 'x' ain't been cooked yet fr (line 7)
expected ')' but got 'be', that ain't it chief (line 5)
can't divide by zero, that's cap (line 2)
bruh what even is '@' 💀 (line 3)
this code been running way too long, go touch grass (line 1)

That last one is the playground's statement budget catching an infinite grind before it freezes your tab.

try/catch

lowkey is try, caught (err) is catch. If the body hits a runtime error, err is bound to the error message as a string and the handler runs instead of crashing the program. 

lowkey {
  cook x be 10 / 0
  yap("never gets here")
} caught (err) {
  yap("caught it:", err)
}

Note: the statement-budget "touch grass" error above is not catchable — it's there to stop runaway loops, not to be handled.

browser games

Define sigma draw() in a program and the playground turns it into a game — it opens a canvas and calls your program's special functions on a loop instead of running it once top-to-bottom. Top-level variables persist across frames, so that's where your game state lives.

functioncalled when
sigma draw()every frame, to render — defining this is what turns a program into a game
sigma update()every frame, before draw — physics / state changes
sigma keypressed(key)on keydown — key is a string like "space", "ArrowUp", "a"
sigma clicked()on mouse click / tap

The game API is only available in the playground's game mode. Colors are CSS color strings — "#5ec6ff", "red", "skyblue".

functionwhat it does
canvas(w, h)set the canvas size
background(color)fill the whole canvas
paint(color)set the fill color for shapes drawn after it
box(x, y, w, h)draw a rectangle
dot(x, y, r)draw a circle
streak(x1, y1, x2, y2)draw a line
words(text, x, y, size)draw text
held(key)is a key currently down → nocap/cap
mouseX() / mouseY()current mouse / touch position
frames()frame counter since start
delta()milliseconds since the last frame

Shape of a game — not runnable inline here since it needs a canvas, but paste it into the playground or just pick flappy bird from the example dropdown there:

canvas(400, 500)
cook birdY be 250
cook vel be 0

sigma keypressed(key) {
  sus (key is "space") { vel be -7 }
}

sigma update() {
  vel += 0.4
  birdY += vel
}

sigma draw() {
  background("#5ec6ff")
  paint("#ffd93d")
  dot(80, birdY, 12)
}

The full game — pipes, scoring, collisions, respawn — is one click away: play flappy bird 🐦.

how it works

The classic Crafting Interpreters pipeline, ~1k lines of TypeScript, no dependencies at runtime:

  1. lexer — source text → tokens, tracking line numbers for errors
  2. parser — recursive descent, tokens → AST (precedence: or → and → equality → comparison → term → factor → unary → call/index → primary)
  3. interpreter — walks the AST with a chain of lexical environments; closures capture their scope; dip/skip/yeet travel as internal signals

Output goes through an injected sink, so the identical core runs the CLI and this site's playground. The full test suite (87 tests) covers the lexer, parser, interpreter, and every builtin.
